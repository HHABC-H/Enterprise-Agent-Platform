# 入库、审批与故障处理手册

## 入库流程

提交 Markdown 文档后，平台先保存当前文档版本，再生成文档变更事件。处理器负责解析文档、按标题切分、建立父子 Chunk 关系、生成检索索引并抽取确定性关系。

入库状态包括：

- `QUEUED`：事件已经排队；
- `PROCESSING`：处理器正在解析或写索引；
- `SUCCESS`：当前版本处理成功；
- `SKIPPED`：内容哈希未变化，幂等跳过；
- `FAILED`：处理失败，需要查看失败原因。

## 审批流程

问答请求默认直接完成检索和回答。对高风险或需要人工确认的问题，可以开启审批开关。证据充分时工作流进入 `WAITING_APPROVAL`，默认审批人是 `reviewer`。审批通过后，工作流继续执行；审批拒绝后，流程结束并返回拒答结果。

审批意见应说明核对依据，例如“已核对引用文档和 Chunk 内容”。不要在审批意见中粘贴密码、访问令牌或不必要的敏感正文。

## RabbitMQ 部署行为

Docker profile 使用 `knowledge.ingestion` 交换机和 `knowledge.document.changed` 路由键，消息进入 `knowledge.ingestion.queue`。处理失败时最多进行有限次数重试，仍失败的消息进入 `knowledge.ingestion.dead` 死信队列。

消息确认与数据库、图数据库写入之间没有分布式事务，因此系统依靠唯一幂等键、内容哈希和“只处理当前版本”规则降低重复投递的影响。死信处理前应先查看任务状态和失败原因，再修复配置或数据问题并重新触发新的事件。

## 常见故障

### 入库后无法问答

先查询入库状态。若状态不是 `SUCCESS`，检查文档正文、版本、租户 ID 和处理失败原因；若状态正常，检查提问用户是否具有文档权限。

### 关系查询为空

确认查询中的租户、文档 ID 和版本与入库请求完全一致，再检查用户权限和最大跳数。空关系不代表接口不可用，也可能表示当前范围内没有可见关系。

### 审批提交失败

检查工作流 ID 是否来自最近一次等待审批的问答，审批人是否为允许的用户，版本是否仍为检查点版本，审批意见是否为空或超长。

### 全文检索不可用

local profile 下使用内存降级实现。Docker profile 下如果 ParadeDB 不可用，平台只能减少全文候选，不应绕过权限过滤和证据校验来强行生成答案。

## 运维原则

先保存 Trace ID、文档 ID、版本和任务状态，再定位日志中的异常类型。不要直接删除知识数据或重置环境；涉及生产数据时，应先备份、确认影响范围并使用可审计的重新入库流程。
