# 企业级 AI 智能体平台可行性验证报告

## 1. 项目结论

项目在 `local` profile 下具备可演示、可测试、可提交的最小闭环：能够完成 Markdown 入库、标题切分、权限感知检索、证据问答、证据不足拒答、人工审批和最小评测。

当前结论是“本地核心链路可行，外部基础设施适配已具备代码与配置但尚未完成真实联调”。

## 2. 验证范围

### 已验证

- Spring Boot 后端测试通过。
- Maven 打包通过。
- 前端 Vite 生产构建通过。
- Compose 文件可以通过静态配置解析。
- P0 同步 Markdown 入库和问答契约保持可用。
- local profile 不要求本机运行 PostgreSQL、Redis、RabbitMQ、Neo4j。

### 未验证

- RabbitMQ 消息发布、消费、重试和死信队列的真实运行结果。
- Neo4j 多跳查询、写入失败恢复和数据持久化。
- ParadeDB BM25 建索引、全文查询和 PostgreSQL 故障恢复。
- Docker profile 全链路启动后的浏览器联调。
- 真实大模型服务开启后的回答质量、延迟和费用。

## 3. 可行性判断

| 维度 | 判断 | 说明 |
| --- | --- | --- |
| 产品闭环 | 可行 | 页面和 API 覆盖入库、检索、问答、审批、评测 |
| 核心安全边界 | 可行 | 检索前按租户、用户和权限过滤；证据不足拒答 |
| 本地演示 | 可行 | 内存仓储和同步事件发布器降低环境要求 |
| 异步扩展 | 设计可行，需联调 | RabbitMQ 交换机、队列、重试和死信配置已提供 |
| 图谱扩展 | 设计可行，需联调 | Neo4j 适配器已提供，查询带版本、租户和权限边界 |
| 全文检索扩展 | 设计可行，需联调 | ParadeDB 适配器已提供，故障时不会绕过证据校验 |
| 生产可用性 | 暂不能判定 | 还需真实数据、压力、故障恢复和安全测试 |

## 4. 技术闭环

```text
Markdown 文档
    -> 文档版本与内容哈希
    -> 标题层级切分为 Chunk
    -> 向量/全文候选召回
    -> 租户与权限过滤
    -> RRF 融合与证据校验
    -> 直接回答 / 明确拒答 / 等待人工审批
```

外部部署时，增量入库路径为：

```text
文档变更
    -> RabbitMQ knowledge.ingestion
    -> knowledge.document.changed
    -> 受控消费与幂等处理
    -> PostgreSQL/ParadeDB + Neo4j
    -> 失败重试，最终进入 knowledge.ingestion.dead
```

## 5. 提交时建议使用的表述

推荐表述：

> 本项目已完成基于 Spring Boot 的企业知识问答最小闭环，在 local profile 下可独立运行并通过自动化测试，支持 Markdown 知识入库、权限感知混合检索、证据引用、证据不足拒答和人工审批检查点。系统同时提供 RabbitMQ、Neo4j、ParadeDB、Redis 的可替换适配器及 Docker Compose 配置，外部服务真实联调作为下一阶段验证项。

不建议表述：

> 已完成所有生产级大模型、图数据库、消息队列和全文数据库联调。

原因是当前验证证据还没有覆盖这些真实运行依赖。

## 6. 下一阶段验收门槛

1. 使用 `.env` 配置非示例密码，启动 Docker Compose。
2. 验证四个基础设施的健康检查和应用启动日志。
3. 入库同一文档两个版本，确认旧事件不会覆盖新版本。
4. 人为制造消费失败，确认重试次数和死信队列行为。
5. 在 Neo4j 和 ParadeDB 中检查数据、权限过滤和版本隔离。
6. 使用真实模型跑一组固定问题，记录准确性、拒答率、P50/P95 延迟和成本。
