## 二、需要实现的功能

### 1. 短期记忆（Short-term Memory）

**存储位置**：Redis

**数据结构**：
Key: session:memory:{sessionId}
Value: List<Message> // 按时间顺序存储
TTL: 24 小时

text

**逻辑**：
- 每次对话，把 user message + assistant message 追加到列表
- 维护一个**滑动窗口（20 条消息）**，超过则移除最早的消息
- 每次调 LLM 时，从 Redis 取完整列表作为 messages 传入

**压缩策略**：
- 设置 token 阈值（如 15000 token）
- 超过阈值时触发压缩：
  - 保留最近 5 轮对话（完整保留）
  - 前 15 轮调用 LLM 生成摘要（使用 LangChain4j 的 summarization）
  - 摘要作为 system 消息放在列表最前面
  - 压缩后的列表写回 Redis

**代码要实现的类**：
- `ShortTermMemoryService` - CRUD + 压缩逻辑
- `MemoryCompressor` - 摘要压缩实现

### 2. 长期记忆（Long-term Memory）

**存储位置**：PgVector

**存储内容**：每条记忆包含
- `content`：记忆原文（如 "用户偏好 Python 简洁风格"）
- `embedding`：1024 维向量（用 text-embedding-v4）
- `metadata`：{ userId, sessionId, timestamp, type, importance }

**记忆类型**（用 type 字段区分）：
- `SEMANTIC`：事实性偏好（用户偏好、个人信息）
- `EPISODIC`：历史事件（"上周写过爬虫，遇到反爬"）
- `PROCEDURAL`：行为模式（"该用户喜欢先确认需求再写代码"）

**写入时机**：
- 会话结束后（用户关闭会话 / 超时）
- 定时任务每 3 小时扫描活跃会话，生成摘要写入
- 用户主动触发（如"记住这个偏好"）

**检索逻辑**：
- 用户发起新会话时，用当前问题做 embedding
- 在 PgVector 中做相似度检索，取 Top-5
- **必须按 userId 过滤**，只能查当前用户的记忆
- 检索时叠加时间衰减：`score = similarity * time_decay_factor`
  - 7 天内：factor = 1.0
  - 7-30 天：factor = 0.7
  - 30 天以上：factor = 0.3

**注入方式**：
- 检索到的记忆拼接到 system prompt 中
- 格式："【历史记忆】{content}（{timestamp}）"

**代码要实现的类**：
- `LongTermMemoryService` - 写入/检索
- `MemoryRetrievalService` - 带时间衰减的检索
- `SessionSummarizer` - 定时总结会话

三、集成到现有对话流程
修改 ChatController 的流程：

text
用户发送消息
    ↓
1. 解析 userId（从 Token/Session）

    ↓
7. 将 user message + assistant message 追加到短期记忆
    ↓
8. 检查短期记忆是否超阈值，超则触发压缩
    ↓
9. 写回 Redis
    ↓
10. 返回响应
